# TCPLink

一个使用 Go 编写的 TCP 并发连接测试工具。图形界面、测试引擎和日志模块编译在同一个可执行文件中，网页界面直接嵌入二进制，通过 WebView 进程内绑定与 Go 通信，不启动本地 HTTP 服务，也没有独立的前端工程。

> TCPLink 只完成 IPv4 解析和 TCP 三次握手。连接建立后不发送 HTTP 请求、不进行 TLS 握手、不传输网页数据。

## 功能

- 实时显示：尝试次数、成功次数、失败次数、当前进行中连接数、拨号中数量、峰值并发、成功率和平均发起速率。
- 出口网卡选择：自动使用系统默认路由，或绑定到指定网卡。
- 测试模式：`TCP 80`、`TCP 443`、`TCP 80 + 443`。双端口模式下每个域名依次测试 80 和 443。
- 发起速率可调：文字输入框，单位次/秒，默认 125，范围 1–1000。
- 84 个内置国内常用网站域名，可在界面中编辑、追加或完全替换为自定义域名。
- 支持直接粘贴网址，自动提取主机名；支持 IPv4 字面量；支持国际化域名（自动转为 punycode）。
- 可设置测试时长（1–86400 秒）和累计失败停止次数（0 表示不限制）。
- 达到时长、失败上限或手动停止后，关闭所有连接并自动保存日志。
- 启动时尝试把文件句柄软上限提升到 32768，但不会超过系统硬上限；界面底部显示实际值。

## 测试原理

1. 域名通过系统解析器解析为 IPv4 地址，成功结果缓存 5 分钟，失败结果缓存 15 秒；一个域名有多个 A 记录时轮换使用。
2. 默认每秒发起 125 次连接（首次连接在测试开始时立即发起，之后平均约每 8 毫秒一次）；可在界面输入框中改为 1–1000 次/秒，实际平均速率会受系统定时精度、拨号耗时等影响。`TCP 80 + 443` 模式的顺序为：域名 A:80、域名 A:443、域名 B:80、域名 B:443……
3. 建立连接时可通过 `Control` 回调绑定出口网卡，同时将本地源地址设置为该网卡的首个 IPv4 地址：
   - macOS：`IP_BOUND_IF`
   - Linux：`SO_BINDTODEVICE`（无权限时回退到源地址绑定）
   - Windows：`IP_UNICAST_IF`
4. 成功连接只保持空闲 TCP 连接，开启 TCP keepalive，最多保持 60 秒，或保持到本轮测试结束。
5. 单次 DNS 解析最多 3 秒，单次 TCP 拨号最多 5 秒。拨号超时、DNS 失败和连接拒绝都计入失败；停止测试时仍在拨号的连接计为“中止”，不计为失败。
6. 达到测试时长、累计失败次数上限或手动停止后，取消所有进行中的拨号、关闭全部已建立连接，然后关闭日志文件并写入摘要。

默认行为：测试时长 60 秒，失败停止 50 次，发起速率 125 次/秒（可调整为 1–1000 次/秒），单连接保持上限 60 秒。

## 构建和运行

### 环境要求

- Go 1.26 或更高版本。
- macOS：Xcode Command Line Tools（`xcode-select --install`）。
- Linux：GTK 3 和 WebKitGTK 开发包。`webview_go` 当前使用 `pkg-config` 查找 `gtk+-3.0` 和 `webkit2gtk-4.0`；只提供 `webkit2gtk-4.1` 的发行版需要自行提供兼容的 pkg-config 名称。
- Windows：WebView2 Runtime 和 C 编译器（CGO）。Windows 构建尚未实测。

### macOS

```bash
go mod download
make build          # 生成 ./TCPLink
./TCPLink           # 直接运行
```

生成可双击的 `.app`：

```bash
make app
open TCPLink.app
```

`make app` 会进行 ad-hoc 签名（`codesign --sign -`），适合本地使用；对外分发需要你自己的开发者签名和公证。

### 其他平台

```bash
go build -trimpath -o TCPLink .
```

### 命令行模式

图形界面之外还提供一个便于快速验证的终端模式：

```bash
./TCPLink -cli -duration 10 -mode both -fail-stop 50
./TCPLink -cli -duration 5 -mode 443 -iface en0 -rate 250 -domains "baidu.com,qq.com"
./TCPLink -list-interfaces
```

参数说明：

| 参数 | 说明 |
| --- | --- |
| `-cli` | 不打开窗口，在终端运行测试 |
| `-mode` | `80`、`443` 或 `both` |
| `-duration` | 测试时长（秒） |
| `-rate` | 每秒发起连接次数，默认 125，范围 1–1000 |
| `-fail-stop` | 累计失败停止次数，0 表示不限制 |
| `-iface` | 出口网卡名称，留空为自动 |
| `-domains` | 逗号或换行分隔的域名；留空使用内置 84 个 |
| `-list-interfaces` | 列出所有网卡及 IPv4 地址后退出 |

## 日志

日志自动保存到当前用户的应用数据目录：

- macOS：`~/Library/Application Support/TCPLink/logs/`
- Windows：`%AppData%\TCPLink\logs\`
- Linux：`~/.config/TCPLink/logs/`

每个会话生成两个文件：

- `tcp-test-<时间>.csv`：每次完成的连接尝试一行，包含时间、域名、IPv4、端口、结果、耗时和错误原因。结果列为 `success`、`failed` 或 `aborted`；测试停止时仍在拨号的连接也会写入一行 `aborted`。文件带 UTF-8 BOM，便于 Excel 打开。
- `tcp-test-<时间>.summary.txt`：配置、最终统计、停止原因、完整域名列表和文件路径。

CSV 每秒至少刷新一次；停止和退出时会强制刷新并同步到磁盘。界面实时日志只保留最近 500 条，可按“全部 / 成功 / 失败 / 中止”筛选，完整记录以文件为准。底部“打开目录”按钮可直接在 Finder/资源管理器中打开日志目录。

## 常见问题

**为什么选择网卡后全部连接超时？**

如果测试目标实际通过 VPN、代理或另一条默认路由出去，强制绑定到某个物理网卡后连接可能不可达。这是网络路由本身的结果，不代表程序故障。需要精确测试某条线路时再选择对应网卡；不确定时使用“自动”。

**为什么进行中连接数没有立刻下降？**

“进行中”表示本进程仍然持有的成功 TCP 连接。对端可能先关闭空闲连接，但程序按设计最多保持 60 秒，并在本地关闭时释放计数。测试结束时会关闭全部连接。

**为什么成功率和我算的不一样？**

成功率定义为 `成功 /（成功 + 失败）`。手动停止时被取消的拨号计入“中止”，不计入失败，也不进入成功率分母。

**把发起速率调得很高会怎样？**

速率 1000 次/秒时平均每 1 毫秒发起一次。如果测试持续超过 60 秒，同时保持的连接数可能达到数万，超过文件句柄软上限后会出现 “too many open files” 一类失败；这些失败会计入失败停止阈值。需要极限压测时，请同时确认系统硬上限和测试网卡/目标网络的承受能力。

**日志会不会包含 HTTP 数据？**

不会。程序只调用 TCP `connect`，从未写入 HTTP 请求或 TLS ClientHello；日志只记录域名、解析出的 IPv4、端口、连接结果、耗时和错误。

**Linux 下绑定网卡提示权限不足？**

较新的 Linux 内核要求 `CAP_NET_RAW` 才能使用 `SO_BINDTODEVICE`。程序会忽略权限错误并继续使用所选网卡的首个 IPv4 作为源地址；如果该网卡没有 IPv4，绑定会失败。也可以使用 `sudo setcap cap_net_raw+ep ./TCPLink` 授权。

## 开发

```bash
go test ./...
go vet ./...
```

测试覆盖内置域名数量（必须为 84）、域名规范化、模式端口展开、内存日志环形缓冲，以及引擎的时长/失败停止计数、连接关闭和成功/中止日志完整性。

请仅在工作负载和授权范围内使用本工具。对目标站点高频建立连接可能触发其防火墙、限流或审计策略。
