# TCPLink

一个使用 Go 编写的 TCP 并发连接测试工具。图形界面使用 [MyGo Native UI](https://github.com/egoist/mygo/blob/main/docs/ui/README.md)（`github.com/egoist/mygo/ui`），由 Go 代码构建并通过 GPU 绘制，与测试引擎和日志模块编译在同一个可执行文件中。不使用 WebView、HTML、JavaScript 或 JSON IPC，也无需独立的前端工程或本地 HTTP 服务。

> TCPLink 只完成 IPv4 解析和 TCP 三次握手。连接建立后不发送 HTTP 请求、不进行 TLS 握手、不传输网页数据。

## 功能

- 实时显示测试统计：运行中显示进行中连接数、拨号中数量、已关闭数量、峰值并发和平均发起速率；空闲或完成后显示尝试、成功、失败、中止次数和成功率。
- 出口网卡选择：自动使用系统默认路由，或绑定到指定网卡。
- 测试模式：`TCP 80`、`TCP 443`、`TCP 80 + 443`。双端口模式下每个域名依次测试 80 和 443。
- 发起速率可调：文字输入框，单位次/秒，默认 125，范围 1–1000。
- 84 个内置国内常用网站域名，可在界面中编辑、追加、完全替换为自定义域名或恢复默认；自定义域名可保存在应用便携目录。
- 支持直接粘贴网址，自动提取主机名；支持 IPv4 字面量；支持国际化域名（自动转为 punycode）。
- 可设置测试时长（1–86400 秒）和累计失败停止次数（0 表示不限制）。
- 达到时长、失败上限或手动停止，以及退出时，统一关闭本轮连接；测试结果仅在显式保存时导出。
- 启动时尝试将文件句柄软上限提升到 65536，不超过系统硬上限，原软上限更高时不降低；界面底部显示实际值。

## 测试原理

1. 域名通过系统解析器解析为 IPv4 地址，成功结果缓存 5 分钟，失败结果缓存 15 秒；一个域名有多个 A 记录时轮换使用。
2. 默认每秒发起 125 次连接（首次连接在测试开始时立即发起，之后平均约每 8 毫秒一次）；可在界面输入框中改为 1–1000 次/秒，实际平均速率会受系统定时精度、拨号耗时等影响。`TCP 80 + 443` 模式的顺序为：域名 A:80、域名 A:443、域名 B:80、域名 B:443……
3. 建立连接时可通过 `Control` 回调绑定出口网卡，同时将本地源地址设置为该网卡的首个 IPv4 地址：
   - macOS：`IP_BOUND_IF`
   - Linux：`SO_BINDTODEVICE`（无权限时回退到源地址绑定）
   - Windows：`IP_UNICAST_IF`
4. 成功连接只保持空闲 TCP 连接，开启 TCP keepalive；没有单连接独立的保持时限，本轮自然结束、手动停止、失败停止或退出时统一释放。
5. 单次 DNS 解析最多 3 秒，单次 TCP 拨号最多 5 秒。拨号超时、DNS 失败和连接拒绝都计入失败；停止测试时仍在拨号的连接计为“中止”，不计为失败。
6. 达到测试时长、累计失败次数上限、手动停止或退出时，取消进行中的拨号并关闭已建立连接。测试记录暂存于系统内部临时缓存，CSV 和摘要仅在显式保存时导出。

默认行为：GUI 和 CLI 测试时长均为 360 秒，失败停止 50 次，发起速率 125 次/秒（可调整为 1–1000 次/秒）。成功连接保持到本轮结束或退出。

## 构建和运行

### 环境要求

- 构建需要 Go 1.27.3 或更高版本，禁用 CGO；无需 C 编译器、Bun 或 Node.js。
- macOS 12 或更高版本：Native UI 使用 Metal；打包 `.app` 需要 macOS 上的 `codesign`。
- Linux（x64、arm64）：运行时需要 GTK 3 库，Native UI 使用 OpenGL；不需要 WebKitGTK。
- Windows 10 或 11（x64、arm64）：Native UI 使用 Direct3D 11，不需要 WebView2 Runtime。

以上系统要求参考 [MyGo 文档](https://github.com/egoist/mygo/blob/main/docs/README.md#requirements)，不代表本项目已经在每种系统和架构上实测。

### macOS

```bash
go mod download
make build          # 生成 ./TCPLink
./TCPLink           # 直接运行
```

生成可双击的 `.app`：

```bash
make app
open TCPLink.app
```

`make app` 会尝试进行 ad-hoc 签名（`codesign --sign -`）；签名失败不会中止打包。对外分发需要你自己的开发者签名和公证。

### 其他平台

```bash
CGO_ENABLED=0 go build -trimpath -o TCPLink .
```

### 命令行模式

图形界面之外还提供一个便于快速验证的终端模式：

```bash
./TCPLink -cli -duration 5 -mode both -rate 10 -domains "127.0.0.1"
./TCPLink -cli -duration 5 -mode 443 -rate 10 -domains "127.0.0.1" -save
./TCPLink -list-interfaces
```

示例仅连接本机的 80/443 端口；若没有相应本地服务，连接会被拒绝。第二个示例显式使用 `-save` 导出结果；默认不导出。

参数说明：

| 参数 | 说明 |
| --- | --- |
| `-cli` | 不打开窗口，在终端运行测试 |
| `-mode` | `80`、`443` 或 `both` |
| `-duration` | 测试时长（秒），默认 360 |
| `-rate` | 每秒发起连接次数，默认 125，范围 1–1000 |
| `-fail-stop` | 累计失败停止次数，0 表示不限制 |
| `-iface` | 出口网卡名称，留空为自动 |
| `-domains` | 逗号或换行分隔的域名；显式指定时优先于便携目录中的配置，否则使用有效配置或内置 84 个 |
| `-save` | 测试结束后显式导出 CSV 和摘要；默认不导出 |
| `-list-interfaces` | 列出所有网卡及 IPv4 地址后退出 |

## 便携目录和域名配置

应用数据位于**便携目录**：普通可执行文件所在目录；macOS `.app` 使用 `.app` 所在目录，而不是 `.app/Contents/MacOS`。不读取或写入旧的用户 HOME 下 Application Support 目录。

便携目录下的 `domains.json` 保存自定义域名，格式例如：

```json
{"domains":["127.0.0.1"]}
```

没有文件时使用 84 个内置域名；未修改默认域名不会自动生成 JSON。界面域名编辑器执行“保存并应用”成功后才持久化自定义列表；启动时存在有效 JSON 则优先使用。文件损坏时会明确提示并安全回退到内置域名，不会自动覆盖损坏文件。显式恢复内置域名并保存会删除本程序管理的自定义 JSON，下次启动使用内置域名。CLI 域名优先级为：显式 `-domains`、有效 `domains.json`、内置域名。

## 保存结果

CSV 和摘要默认均不导出。GUI 测试结束后点击“保存结果”，或在 CLI 使用 `-save`，才会在便携目录下的 `logs` 中创建唯一会话目录并生成两个文件。这里的 `logs` 是便携目录的子目录，不是 `~/logs`。启动时不会创建导出目录或文件；仅显式导出或点击“打开目录”时才创建 `logs`。若路径不可写，程序明确报错，不会悄悄回退到其他目录。

目录结构示例（会话目录名为示意）：

```text
便携目录/
└── logs/
    └── tcp-test-<会话标识>-<唯一后缀>/
        ├── results.csv
        └── summary.txt
```

每次保存的结果包含：

- `results.csv`：每次完成的连接尝试一行，包含时间、域名、IPv4、端口、结果、耗时和错误原因。结果列为 `success`、`failed` 或 `aborted`；测试停止时仍在拨号的连接也会写入一行 `aborted`。文件带 UTF-8 BOM，便于 Excel 打开。
- `summary.txt`：配置、最终统计、停止原因、完整域名列表和文件路径。

同一会话在同一目录重复保存时会复用已保存的路径，不会重写文件；如果已保存文件缺失或不可用，程序会报错。

为避免长时间测试的全部记录占满内存，完整记录暂存于系统内部临时缓存，而不是默认导出的 CSV 或摘要。界面约每 200 毫秒读取一次快照，实时日志缓冲显示最近 600 条，支持按“全部 / 成功 / 失败 / 中止”筛选和自动跟随；清空只影响视图，显式保存的完整结果不受筛选、清空或裁剪影响。

开始新测试替换当前会话或正常退出时会清理临时缓存；**未手动保存的结果会丢失**。异常退出可能残留临时缓存，不能保证恢复未保存的结果。

## 常见问题

**为什么选择网卡后全部连接超时？**

如果测试目标实际通过 VPN、代理或另一条默认路由出去，强制绑定到某个物理网卡后连接可能不可达。这是网络路由本身的结果，不代表程序故障。需要精确测试某条线路时再选择对应网卡；不确定时使用“自动”。

**为什么进行中连接数没有立刻下降？**

“进行中”表示本进程仍然持有的成功 TCP 连接。对端可能先关闭空闲连接，但程序没有独立的单连接保持时限；本轮结束或退出时会统一关闭本地持有的连接。

**为什么成功率和我算的不一样？**

成功率定义为 `成功 /（成功 + 失败）`。手动停止时被取消的拨号计入“中止”，不计入失败，也不进入成功率分母。

**把发起速率调得很高会怎样？**

速率 1000 次/秒时平均每 1 毫秒发起一次。成功连接持续保持至本轮结束，默认 360 秒 × 125 次/秒理论上就可能累计约 45000 个连接；实际数量受连接成功率、资源限制和发起速率影响。超过文件句柄软上限可能出现 “too many open files” 一类失败，并计入失败停止阈值。高负载测试前，请确认系统软硬上限以及本机、网卡和目标网络的承受能力。

**日志会不会包含 HTTP 数据？**

不会。程序只调用 TCP `connect`，从未写入 HTTP 请求或 TLS ClientHello；日志只记录域名、解析出的 IPv4、端口、连接结果、耗时和错误。

**Linux 下绑定网卡提示权限不足？**

较新的 Linux 内核要求 `CAP_NET_RAW` 才能使用 `SO_BINDTODEVICE`。程序会忽略权限错误并继续使用所选网卡的首个 IPv4 作为源地址；如果该网卡没有 IPv4，绑定会失败。也可以使用 `sudo setcap cap_net_raw+ep ./TCPLink` 授权。

## 开发

```bash
CGO_ENABLED=0 go run .
CGO_ENABLED=0 go test ./...
CGO_ENABLED=0 go vet ./...
```

`go run` 使用临时编译的可执行文件，其便携目录是该临时可执行文件所在目录；若要在项目目录旁使用稳定的本地数据，建议先运行 `make build`，再运行生成的 `./TCPLink`。

测试覆盖内置域名数量（必须为 84）、域名规范化、模式端口展开、内存日志环形缓冲，以及引擎的时长/失败停止计数、连接关闭和成功/中止日志完整性。

请仅在工作负载和授权范围内使用本工具。对目标站点高频建立连接可能触发其防火墙、限流或审计策略。
